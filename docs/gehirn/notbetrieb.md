# Notbetrieb (ohne Claude)

Teil des Projekt-Gehirns (Übersicht: CLAUDE.md). Nur lesen, wenn die Aufgabe dieses Thema berührt.

- **Notbetrieb** (Claude-Limit erreicht; Doku `docs/notbetrieb-einrichten.md`): Alle Arten (ranking, `fakten`, `erklaer`, story, reportage, satire, clip) laufen im Notbetrieb in einem Zug; „bearbeiten“/„hochladen“ per neuem Issue mit `bezug` (Artefakt des früheren Laufs, `notbetrieb.restore_earlier`); Modellausfall → ein Wiederholungslauf nach 10 Min. (`run_with_retry`) (`notbetrieb.prepare_order`, Story-Skelett → direkt Video; `fakten` = `job._fakten`/`planner.plan_facts`, ohne Modell ehrlicher Abbruch); Modell-Kette `llm.providers()` CUDI_LLM_* → CUDI_LLM2_* → CUDI_LLM3_* (429/5xx: 1 Wiederholung), dann Regelweg. Standardweg = **GitHub-Issue** (Hugging Face verlangt für Docker-Spaces PRO/402): Banner „Notbetrieb öffnen“ der App-Seite öffnet `issues/new` mit Marker `cudi-auftrag` und App-Auftrag als JSON-Block (`nbIssueLink`, URL ≤ 6000 Zeichen, alle Arten im ganzen Lauf); `auftrag.yml`/`auftrag.py` (`extract_json`, `build_json_order` → `job.parse_order`, Kennung `gh<Nr>`) startet `notbetrieb.yml` → `.github/scripts/notbetrieb.py` (`run`: `job.run_order(via_claude=False)`, Hochladen direkt, `freigabe:false`; `melden`: Kommentar mit Texten/`upload_note`/Prüfbericht-Kurzform + Artefakt-Link, Erfolg schließt das Issue). Secrets `CUDI_LLM_*` (+ optional Pexels/Pixabay/YT/TikTok). Repo öffentlich → Issues/Artefakt-Links sichtbar. `handoff.request` fragt ohne `CUDI_SCHREIBEN` ein freies LLM (`CUDI_LLM_*`, Gemini; `handoff.active()`/`llm_mode()`, Fehler → None → Textbausteine). Optional/alt: Web-App-Space (`cloud-app.yml` nur manuell, überspringt ohne `HF_TOKEN`/bei 402; `POST /api/auftrag`); steht `config/notbetrieb.url`, öffnet der Banner diese Adresse statt GitHub (`?demo=limit` zeigt den GitHub-Weg).
